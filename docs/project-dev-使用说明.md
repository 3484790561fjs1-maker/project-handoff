# project-dev 简明实操指南

以后统一说 **`使用 $project-dev，……`**。小项目和复杂项目用同一套流程，AI 按需安排最多两路并行。

下面以 `toolbox` 工具箱为例。做其他项目时，替换项目名、功能和业务仓库地址。

## 1. 另一台电脑：安装一次

当前电脑已经安装。另一台准备好 Codex、Git 和 GitHub 仓库访问权限，在 Codex 发送：

```text
从我的私有仓库 3484790561fjs1-maker/project-handoff 的 main 分支，
安装 skills/project-dev 和 skills/project-handoff。
缺少的使用 skill-installer 安装；已存在的先检查差异，备份并保留本地定制后再更新。
请使用本机已有的 GitHub 登录凭据。
```

技能未出现时重启 Codex。Superpowers 需另装；未安装时会使用基础需求与计划流程。遇到登录提示，在官方界面操作，不用发送密码。

## 2. 第一晚在家：创建项目

新建一个空文件夹，例如 `D:\Projects\toolbox`，在 Codex 打开它，发送：

```text
使用 $project-dev，创建一个中文工具箱。
首批功能：JSON 格式化、时间转换、图片压缩。
先对齐需求并保存设计文档；UI 按我随后提供的规则出方案，等我选好后制定计划并开发。
先跑通公共框架和一个工具，再按任务依赖决定是否并行，以速度和总 token 消耗为依据。
在账号 3484790561fjs1-maker 下创建 toolbox 私有仓库并上传本项目；同名仓库存在时先核对用途。
建立规则、架构、进展和环境说明，配置好换电脑接续开发。
```

之后按提示补充需求、提供 UI 规则并选择方案。这个项目使用独立的 `toolbox` 仓库，Skill 仓库只用于安装和更新。

## 3. 开发中：直接提功能

```text
使用 $project-dev，给图片压缩工具增加批量处理和压缩前后大小对比。请实现、验证并更新进展。
```

不用手动开多个聊天；适合并行时由 AI 在独立工作目录和分支分工。不适合并行的任务直接完成。

## 4. 晚上结束：收工上传

```text
使用 $project-dev，收工同步，明天我要换电脑继续。
先停止本批任务写入，保存各分支的代码与未完成进展，更新交接资料，提交推送并核验远端。
最后告诉我下一步，以及哪些内容还只在本机。未完成功能不强行合并到 main。
```

看到相关分支均已推送并核验后再换电脑。功能做到一半也可以收工。

## 5. 第二天到公司：接着开发

**第一次接手：** 完成安装后，在 Codex 打开项目父文件夹，例如 `D:\Projects`，发送：

```text
使用 $project-dev，把业务仓库克隆到当前文件夹下的 toolbox：
https://github.com/3484790561fjs1-maker/toolbox.git
目标目录已存在时先核对，不覆盖。
执行开工同步，读取最新规则、架构、进展和未完成任务，检查开发环境。
告诉我要打开的项目完整路径、上次做到哪里和下一步。
```

仓库地址换成实际创建成功的业务仓库。然后打开返回的项目文件夹，发送下面这句；以后每天开工也用它：

```text
使用 $project-dev，开工同步。同步成功且环境就绪后，接着上次已确定的下一项任务开发。
```

公司收工同样用第 4 步，回家再用开工提示词。

## 6. 可选：保存稳定版本与回退

一个阶段做好，想合并并留下版本标记时：

```text
使用 $project-dev，验收本阶段。将通过审查和组合验证的功能合并到 main 并推送，更新变更记录。
在验收通过的 main 上创建并推送 v0.1.0 标签；已有同名标签不要覆盖。
```

之后每个阶段换用新版本号，例如 `v0.2.0`。想恢复旧版本时：

```text
使用 $project-dev，将 main 的项目内容恢复到 v0.1.0。
先保护本地未提交修改，用新的恢复提交保留历史，验证后推送，不强推。
```

日常开发保留在开发分支，稳定版本保留在 `main`，AI 按约定处理。代码回退不恢复线上数据库或部署。

记住：**每台电脑安装一次；每次开工同步，结束收工同步。** 接续依据仓库中的资料，聊天记录、运行中的任务、真实密钥和本地数据库不会自动带过去。
