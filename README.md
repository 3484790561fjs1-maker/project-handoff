# project-handoff · 项目交接

让家里和公司的两台电脑接着开发同一个项目。收工时更新进展、提交并推送；开工时检查本地状态、拉取代码、读取规则和交接资料。

这是一个 Codex Skill。操作在你发出指令后由 Codex 执行，不是后台自动同步服务。版本：**1.0.0**。

GitHub 仓库：[3484790561fjs1-maker/project-handoff](https://github.com/3484790561fjs1-maker/project-handoff)（私有，下载时需登录有访问权限的账号）。

## 在另一台电脑安装

准备好 Codex、Git，并让 Git 能访问你的 GitHub 私有仓库。网页已登录与 Git 已登录是两回事；遇到登录提示，在官方登录界面完成，不要把密码或令牌发进聊天。

在 Codex 中发送：

```text
使用 skill-installer，从 GitHub 仓库 3484790561fjs1-maker/project-handoff 安装 skills/project-handoff。
这是我的私有仓库，请使用这台电脑已有的 GitHub 登录凭据。
```

安装完成后，下一轮对话即可使用。如果技能列表未刷新，重新打开项目或重启 Codex 后再使用。

也可以在 GitHub 登录上述账号，点击仓库的 **Code → Download ZIP**，解压后把其中的 `skills/project-handoff` 整个文件夹复制到 Codex 的技能目录：

- Windows 默认：`C:\Users\你的用户名\.codex\skills\project-handoff`
- macOS / Linux 默认：`~/.codex/skills/project-handoff`
- 如果设置了 `CODEX_HOME`：放到该目录下的 `skills/project-handoff`。

最终目录应直接包含 `SKILL.md`、`agents`、`references`、`assets`，不要多套一层同名文件夹。私有仓库需有访问权限；业务项目本身不会安装或更新这份通用 Skill。

## 新项目第一次使用

先在 Codex 中打开你准备存放项目的文件夹，然后发送：

```text
使用 $project-handoff 初始化交接。
我要做一个待办清单网站，支持添加、删除、标记完成和刷新后保留任务。
请建立项目规则、架构和进展文档，再开始实现添加、删除功能。
项目要同步到 GitHub；需要仓库地址时告诉我。如果我已提供地址，请核对后使用。
```

Skill 会根据真实项目补齐下列文件，已有内容会保留并合并。不会凭空选择技术栈或把未实现的功能写成已完成。

```text
AGENTS.md                  固定规则和交接入口
.project-handoff.json      远端、分支、文档位置、检查命令
README.md                  安装、运行、测试和环境要求
docs/ARCHITECTURE.md       架构、模块职责与数据流
docs/STATUS.md             已完成、验证情况、问题和下一步
docs/DECISIONS.md          重要技术选择和原因
```

“初始化交接”本身只配置交接。创建仓库、实现功能等操作，以你当次的完整要求为准。

## 每天怎么用

### 收工

```text
使用 $project-handoff，收工同步。明天我要在另一台电脑继续。
```

Codex 会核对分支和修改范围，执行适合本次修改的检查，更新交接文档，提交并推送。最后给出分支、提交号、远端确认结果、检查情况及仍在本机的内容。

“收工同步”包含向已核实的项目远端提交和推送的授权；不会自动发布网站、部署、合并 PR 或修改仓库权限。推送失败会明确报告，不会把本地提交说成同步成功。

### 开工

另一台电脑第一次接手时，把业务项目仓库克隆下来，然后**在 Codex 中打开克隆后的项目文件夹**。之后发送：

```text
使用 $project-handoff，开工同步。
```

Codex 会检查本地修改和所在分支，获取远端更新，在能安全快进时更新代码，重新读取最新规则和交接文档，检查开发环境，告诉你接下来从哪里继续。

如需顺便执行任务，可以直接说：

```text
使用 $project-handoff，开工同步，然后继续完成昨天留下的本地存储功能。
```

只说“开工同步”时会先完成同步和交接摘要，不会自行执行整份待办列表。

### 正常开发

照常提需求即可。项目的 `AGENTS.md` 会约定“开工同步／收工同步”的含义；显式写出 `$project-handoff` 更容易触发。架构或重要决定变化时同步维护对应文档，收工时再核对一次。

## 遇到特殊情况

| 情况 | 处理方式 |
| --- | --- |
| 本机仍有未提交修改 | 保留工作并说明阻塞，不直接覆盖、丢弃或自动暂存起来 |
| 本地和远端分别产生了提交 | 报告分叉和可选处理；不自动变基、合并或强推 |
| 不确定继续哪个分支 | 先核实分支；不默默切到 main |
| 功能只写了一半 | 可以交接开发分支，记录 WIP 和未通过检查；不伪装成完成 |
| 存在未推送的本地提交 | 核对提交内容属于当前项目交接范围后再推送 |
| 缺少密钥、数据库或运行环境 | 记录具体缺项；代码同步与环境就绪分别报告 |
| GitHub 无法访问或登录失效 | 保留本地成果，明确未完成远端交接，并给出恢复步骤 |

项目应提交依赖锁文件、数据库迁移和不含密钥的 `.env.example`。真实 `.env`、数据库业务数据、密钥、未提交改动和聊天记录不会随代码自动迁移。

## 更新 Skill

Skill 的更新与业务项目拉取分开进行。在需要更新的电脑上发送：

```text
请从 3484790561fjs1-maker/project-handoff 的 main 分支更新我安装的 project-handoff。
先检查并保留我的本地定制；确认来源和差异后再替换技能文件，不要改动业务项目。
```

也可以下载新版 ZIP，备份已安装的 `project-handoff` 文件夹后，用新版技能文件夹替换。内置安装器遇到同名技能会停止，不要把“重新安装”误认为自动更新。

## 检查是否装对

发送“使用 $project-handoff，检查当前项目是否已经配置交接，先不要提交或推送”。Codex 应报告技能来源、项目根目录、远端和分支、文档是否齐全以及缺失项。

没有安装 Skill 的电脑仍可阅读项目中的规则和交接文档，但不能据此假设完整交接流程已经执行。
