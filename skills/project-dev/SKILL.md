# 项目开发

一个主对话负责当前阶段交付，按任务依赖选择执行方式。默认简体中文，沿用项目和用户已有技术、UI 与协作规则。

## 入口与按需读取

| 用户意图 | 读取与执行 |
| --- | --- |
| 创建项目、初始化统一流程、确定需求或设计 | [references/start.md](references/start.md) |
| 继续开发、实现一项功能、按计划推进、排错 | [references/develop.md](references/develop.md)；仅在确有独立大任务时追加 [references/parallel.md](references/parallel.md) |
| 开工同步、换电脑继续、收工同步 | [references/sync.md](references/sync.md) |
| 验收并合并、发布一个版本 | develop 中的集成与交付；发布目标按用户实际要求，不因收工自动发布 |
| 仅分析、解释或选型 | 只完成分析，不初始化业务项目或启动工作者 |

不要因用户提及某个阶段就读完全部参考。先区分用户是在描述使用方式，还是要求实际执行。

## 项目事实源

确认业务项目根目录，读取适用的 `AGENTS.md`。首次接手读取 `.project-dev.json`、`.project-handoff.json`、当前进展；架构、需求、计划和决策只读本任务相关部分。同一对话复用已核验且未变化的信息；拉取更新、切换分支、发生压缩或任务变化时刷新受影响部分。

- `.project-handoff.json` 保存远端、主控交接分支、环境和已有文档路径，不在新配置中复制这些信息。
- `.project-dev.json` 保存执行偏好、需求/计划/任务文档位置与 UI 规则引用；沿用已有等价文档，不另建一套总进展。
- Git、实际代码和验证证据用于核对状态；计划不能写成实现，工作者自述不能直接写成验证通过。
- 进展保留当前快照，历史放 Git/PR。主控维护总进展，工作者只写自己的任务说明。

## 执行原则

默认由主对话直接实施；本流程明确选择直接执行为默认路径。必要时委派独立任务给子代理，不要求用户按项目大小选模式。初版最多两个编码执行者同时工作，主对话参与编码时也计入；平台限制更低时采用更低值。共享设计和相互依赖的任务先集中完成。

并行写代码必须先验证每个任务拥有独立 Worktree、分支和文件职责。子代理默认不代表文件隔离。不能创建并验证隔离时改为单路执行；不在同一检出目录冒险并发。独立桌面聊天仅在用户明确要求新建聊天时创建；普通分工优先在当前任务内使用可用子代理。

## 组件接入

- 已安装 `project-handoff` 时，初始化和推拉交接复用它，统一入口追加多任务汇总；找不到时按 sync 的基础流程执行并说明降级。
- 若当前可用技能中有 Superpowers，需要需求对齐时用 `brainstorming`，已确认设计需要计划时用 `writing-plans`，直接实施优先其 `executing-plans`；调试和审查按需接入。不要为了每个小修改重跑完整流程。
- 未安装 Superpowers 时用本 Skill 的基础需求/计划流程，明确未调用原插件。用户明确指定必须使用某个缺失组件时，完成独立部分后说明缺项，不冒充执行。UI 使用用户指定规则，未提供时记录待接入。
- 不为探测组件每轮联网搜索；不自动安装整个插件包或修改全局配置。本技能不包含 Superpowers 的源码或插件。

## 权限与完成标准

“收工同步”授权提交并推送已核实的本项目相关代码和交接资料；已有授权继续有效。合并、标签、Release 和部署按用户明确要求及项目约定执行。“初始化”本身不授权创建 GitHub 仓库。保护已有修改、暂存内容和其他任务；不用强推、丢弃、自动 stash 或改写历史来达成同步。

用户只要求接手或分析时，到该结果为止；要求继续开发时完成当前已确定的功能或阶段，不自行无限扩展待办。报告结果、验证、实际分支/提交、下一步和阻塞；同步需区分文档落盘、本地提交、远端核验，不能混为成功。
