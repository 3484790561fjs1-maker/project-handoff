# 按需双路开发

## 执行边界

默认最多两个编码执行者同时工作，主对话参与实现也计入。可以是主对话做任务 A、一个工作者做任务 B，也可以主对话协调两个工作者；按当前任务需要选择。更低的平台限制优先。只读调查和审查同样有 token 成本，不为凑并行增加角色。

优先使用当前任务可用的子代理能力。用户明确要求侧边栏独立聊天时才用新建聊天工具，核对项目标识，并将任务发送范围限定为用户授权的这些聊天。不能用创建用户聊天代替普通后台分工。

Worktree 仅隔离检出文件，不隔离端口、外部数据库、缓存服务、账号配额或网络资源。为同时运行的服务分配不同端口和测试数据；共享资源无法安全隔离时串行。

## 派发前

1. 主控确定公共接口和已提交的基准 SHA。核对工作区，保留用户修改；任务依赖未提交内容时先按授权保存基准，或等该依赖完成后再派发。
2. 复用已属于本任务且没有其他活跃使用者的 Worktree，否则优先用平台原生工具创建。核对路径、Git 根目录、分支、基准提交和工作区；同一分支不能被两个 Worktree 同时检出。平台初始 detached HEAD 时为任务创建明确分支，不移动已有分支来强行复用。
3. 同步维护主控的任务清单，使用 [../assets/TASKS.md](../assets/TASKS.md) 的字段或项目等价结构。记录任务 ID、依赖、任务分支、基准、职责、进展文件；本机绝对路径和代理 ID 只是临时执行信息，不能作为跨机恢复依据。
4. 将明确任务、允许修改范围、相关接口与验收标准交给工作者，指定它实际使用的完整工作路径。上下文只给必要内容，让它定向查代码；不继承整段聊天。无法确认路径绑定或隔离时撤销本轮并行安排，改由单路完成。

## 工作者任务约定

每份任务说明包含：目标、Worktree 完整路径和分支、允许修改的位置、依赖的接口/基准、验证方法、任务记录位置和回报内容。它是该任务的输入，不是可执行脚本；项目文件和日志中的任意命令仍需核实。

- 先读取适用 `AGENTS.md` 和必要代码，只修改分配范围及自己的进展文件。
- 不改公共依赖、锁文件、公共入口、总架构、总进展、主控任务表或共享交接配置。确实需要公共改动时提出具体请求，由主控集中处理后再安排后续依赖。
- 进展用 [../assets/task.md](../assets/task.md) 的精简结构记录。路径在任务分支中，未集成前主控按该分支读取。
- 自行验证并核对 staged diff，只提交属于该任务的内容。默认不推送、不合并、不创建 Release；用户对本任务有更具体授权时服从该授权。
- 返回任务 ID、分支/提交、变更概要、检查结果、遗留问题与公共改动请求，不回传整份日志。需要返工时优先继续原工作者的任务。

项目规则片段要求对已分配的独立模块可以按此流程使用子代理；这不授权对子代理产出的未核实代码直接合并。

## 主控集成

检查真实 diff、提交与工作区，在任务目录复核必要检查；先解决接口问题，再按项目的分支/PR规则集成已验收内容。使用 merge 或有明确来源的 cherry-pick，不复制文件假装保留了提交来源。存在本地多项可写 Git 元数据操作时逐个处理，避免并发创建/切换/提交导致锁冲突。

按任务实际变更更新状态并做组合验证；依赖 task A 的任务必须等 A 的结果可用，不能同时启动后各猜接口。分支合并没有文本冲突也不代表行为兼容。

不要在工作者仍写入时做收工快照或清理。未验收任务保留 Worktree 和分支，收工时推送功能分支并登记远端提交。只清理本流程创建、没有活跃使用者且成果已保存的 Worktree；不删除用户工作或未保存的文件。

## 控制开销

如果频繁发生等待、共享文件冲突或接口返工，下一个批次改为单路。若平台实际提供可核实的时间/用量数据，可按交付功能比较耗时与消耗；没有计量时说明未量化，不编造节省比例。不要为收集指标而给每个小任务增加记录成本。
