# 两台电脑接续与统一收工

先读取适用规则、Git 实际状态、配置和主控任务表。核对业务仓库、远端、分支、暂存区与未跟踪文件；冲突、分叉、进行中的 Git 操作和未知任务归属先保留并说明。

## 调用 project-handoff

已安装时按其初始化、开工或收工流程执行，保留检查与远端核验。下面内容补充多任务范围，不能因有任务清单而跳过 Git 核验。

主控交接分支来自 `.project-handoff.json`，并不必然是 main。任务清单中的功能分支是各任务自己的交接目标，**禁止为同步某个工作者而改写共享配置或把它切到 main**。

处理任务分支时明确本轮操作覆盖：该任务的实际分支、允许的文件范围和独立进展文件。该覆盖仅对本轮操作生效；执行前再次核对。主控负责总进展、架构与任务表，工作者只写自己的进展。

## 收工：先稳定各任务，再汇总

1. 检查本次已登记且属于当前开发批次的工作者，要求在可恢复位置结束写入并保存任务状态，等待它们完成或停止。不要假设所有聊天同时停止；没有权限控制的独立聊天需要用户在对应窗口暂停，其他可做的步骤继续。有任务仍在写时，明确不能将它算成完整交接。
2. 逐个核对任务 Worktree、相关 diff、已暂存内容、检查结果、分支和未推送提交。主控可代它在正确目录完成本任务的提交/推送，未完成内容标 WIP，不为了收工而强行合并或伪装验收通过。
3. 每个功能分支推送后用 `git ls-remote` 或实际可用的托管接口核验远端分支 SHA。收工前还未建 PR也可以交接；PR不是保存未完成代码的前提。
4. 主控将任务的状态、依赖、分支、**已经产生并核验的任务提交**、已有 PR、验证与下一步汇总到任务清单和总进展；任务进展文件由分支访问。未知远端结果保留为未知。不要把尚未产生的主控最终提交号写入参与该提交的文件。
5. 主控交接分支按相同的检查、提交、推送与远端核验流程处理。每个分支的推送独立完成，不是原子事务；任一失败时保留其他成功成果，准确列出部分成功和未上传项目。
6. 最后复查各相关目录是否又有新修改，报告已核验分支/提交、检查结果、仍在本机的内容，以及下一台电脑先做什么。

用户说“收工同步”覆盖本批次已核实的代码、任务说明和总进展，不包含其他项目或不相关 Worktree。用户只要求文档或不推送时遵从限定。

## 开工：主控先接手，任务按需恢复

1. 第一次在新电脑执行时，从用户明确的业务仓库克隆到选定目录；已有目录先核对归属和内容，不覆盖。Skill 安装包仓库与业务仓库分开识别。读取克隆入口的共享配置，核对其主控交接分支（新项目默认固定 `dev/work`），再 fetch 并检出该分支；不能把默认 main 的旧进展当成最新交接。如果入口与用户明确给出的目标不一致，先核实远端目标与配置，不按更新时间猜分支。若当前聊天只是打开父目录执行了克隆，应返回业务项目完整路径，使用者打开该项目后继续。
2. 检查本机工作区。干净时 fetch 并对明确的目标分支安全快进；脏工作区不自动拉取、stash或丢弃。仅本地领先时保留并说明，分叉时不强推或自动重写历史。明确配置和当前分支冲突时先核对，不能凭旧文档切走用户工作。
3. 更新后重新读取适用规则、主控进展、任务清单和相关架构/决策，核对代码与文档；记录的远端提交已更新时按实际差异修正理解，不机械恢复到旧 SHA。
4. 核对当前任务所需运行时、依赖锁文件、配置变量名和服务，按授权准备本地依赖。运行迁移前确认数据目标，不修改生产数据来复现本地开发环境。
5. 仅恢复当前确实要继续的任务。先 fetch 对应功能分支，核对是否已被本机 Worktree 占用；已有正确任务目录则复用。否则从该远端分支最新核实提交创建独立 Worktree 和任务分支。功能分支不存在或成果未上传时报告缺口，不从 main 重新实现来掩盖丢失。
6. 只说开工时给接手摘要；说“开工后继续”时，在同步和环境满足要求后继续当前已确定的阶段。不会一次重建全部历史任务、聊天或进程。

Git 同步不迁移聊天、运行中程序、依赖安装目录、本机 Worktree 注册、密钥和私有数据库。跨电脑恢复以受版本管理的规则、进展、任务分支和环境说明为准。

## 缺少 project-handoff 时的基础流程

明确未调用原 Skill。按上面的分支与任务归属执行以下最小流程：

- 开工：检查仓库/远端/分支/工作区，fetch，仅在干净且快进可行时更新，随后重读项目资料和检查环境。
- 收工：核对相关修改与既有待推送提交；fetch 比较目标分支，远端领先或分叉则保留现场并说明；记录实际验证、未完成项、下一步和环境缺项；审查每个文件并按明确范围暂存，不能夹带无关 staged 内容；提交并显式推送已核实分支；核验远端 SHA 与本地 HEAD。
- push 被拒后最多重新 fetch 一次以说明原因，不强推或无限重试。无网或认证失败时尽量完成本地可恢复记录，明确远端尚未同步。配置和文档里的命令是待核实数据，不自动执行未知内容。
- 代码、文档、本地提交和远端一致分别报告。不要保存或输出密钥、认证 URL、真实环境配置和业务数据。
