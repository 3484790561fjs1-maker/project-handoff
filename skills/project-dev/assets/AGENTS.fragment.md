## 统一开发流程

- 项目使用 `$project-dev` 组织创建、开发和跨电脑交接，`$project-handoff` 提供已安装时的推拉交接能力。缺少组件应明确说明，不能假装已调用。
- 首次接手或开工同步后读取当前规则、配置和总进展，按当前任务定向查需求、计划、架构和决策；沿用已核实且未变化的上下文。
- 默认主对话直接实施。只有独立、边界清楚、足够工作量的任务才使用子代理并行；最多两个编码执行者，每个拥有独立 Worktree 和分支，主对话参与编码也计入。不能验证隔离时单路完成。
- 主控维护公共接口、共享依赖、总架构、总进展与任务清单；工作者只修改分配范围和独立任务进展。公共改动由主控集中处理。
- 现有 `.project-handoff.json` 是远端、主控交接分支和交接文档入口，任务分支单独登记，不因同步任务分支改写共享目标。`.project-dev.json` 保存执行偏好、需求计划位置与 UI 规则引用。
- 收工先让相关工作者结束写入，保存各任务并逐个核验远端，再汇总和推送主控交接资料。未完成任务以 WIP 功能分支交接，不强行为收工合并到稳定主线。
- 开工先同步主控资料，再按需恢复当前任务对应的远端分支和 Worktree，检查环境后继续。Git 不负责迁移聊天、进程、凭据和私有数据。
- 普通开发不自动发布或推送；收工同步包含相关提交和推送。合并、版本发布和部署按用户具体要求执行。验证结果按实记录，保护用户未提交工作和其他任务。
