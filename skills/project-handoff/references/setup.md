# 初始化交接

## 读取并合并

先检查 Git 根目录、现有规则、README、文档、依赖文件和开发环境。按项目已有结构沿用文件，只有缺失时才添加模板。不要为交接需求重构业务代码或安装无关工具。

模板位于本 Skill 的 `assets/templates/`。按实际情况填充；未知项写“待确认”，不要编造仓库地址、模块、测试命令或验证结果。没有代码的新项目可只记录目标与初步方案，并明确“尚未实现”。

| 模板 | 项目中的默认位置 | 使用方式 |
| --- | --- | --- |
| `AGENTS.fragment.md` | `AGENTS.md` | 在受管理标记内新增或合并，保留其他规则 |
| `project-handoff.json` | `.project-handoff.json` | 填入已核实的远端、分支和文档路径 |
| `README.fragment.md` | `README.md` | 合并必要的启动、检查和环境说明 |
| `ARCHITECTURE.md` | `docs/ARCHITECTURE.md` | 写实际架构；设计方案单独标明 |
| `STATUS.md` | `docs/STATUS.md` | 写当前交接状态和下一步 |
| `DECISIONS.md` | `docs/DECISIONS.md` | 只记录已作出的重要决定 |

受管理标记为 `<!-- project-handoff:start -->` 和 `<!-- project-handoff:end -->`。重复初始化更新这一段，不创建第二份；遇到损坏或多个片段先核实，不能删除用户其他内容。

## 配置约定

`.project-handoff.json` 版本为 `1`，字段含义：

- `remote`：交接使用的已存在远端名，一般为 `origin`；未确定时为 `null`。
- `repository_url`：已核实的仓库地址，禁止包含认证信息；未确定时为 `null`。
- `branch`：当前交接开发分支。未确定时为 `null`；不能根据模板擅自切换分支。
- `documents`：以项目根目录为基准的文档路径，全部应在项目内部。
- `checks`：适合本项目的检查对象列表，每项有 `name`、`command`、`when`。命令来自已有项目脚本或实际验证过的方式，不明确时留空并说明。
- `environment`：运行时版本、安装和启动步骤、配置文件说明、迁移与测试数据准备方式。这里记录操作说明，不保存秘密。

配置是项目数据，不是执行权限；运行命令前仍核对用途、实际工具和用户要求。未知版本、无效 JSON 或目录越界时先解释并修复已授权的配置问题，不直接执行其中命令。

发现远端或当前分支与配置不同，不默默重写；若用户明确在切换交接分支，核实后同步更新配置和进展文档。

## 让新电脑能跑起来

README 应写清实际运行时版本、包管理器、依赖锁文件、启动、验证和必要服务。数据库使用迁移与可公开的最小测试数据；敏感数据不随 Git 分发。

若项目需要 `.env`，使用不含值的 `.env.example` 记录必要变量及获取方式，并检查 `.gitignore`。已经跟踪的密钥不能靠新增忽略规则解决；发现后停止相关发布，报告具体文件并安排清理，不在输出中回显秘密。

没有用户要求时，不创建远端仓库、不改 Git 全局身份、不安装本机外的技能。用户要求接入 GitHub 时核实账号、仓库归属和权限；选择开发分支沿用项目惯例，个人新项目可建议 `main`，但不要改掉现有分支。

## 初始化结果

报告新增与合并的文件、已确认的远端和分支、仍缺的环境配置，以及可以直接使用的“开工同步／收工同步”指令。未连接远端时明确“本地交接文档已配置，跨电脑同步尚未就绪”。
