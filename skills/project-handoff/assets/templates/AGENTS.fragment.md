## 项目交接约定

- 在开始实现前读取 `.project-handoff.json` 指向的项目说明、架构、进展和重要决策；没有配置时读取 README.md 和 docs 下的对应文档。相关目录的现有规则同样适用。
- 用户说“初始化交接”“开工同步”“收工同步”时，使用已安装的 `$project-handoff`。若不可用，明确说明并根据本段执行可行步骤，不假装已加载 Skill。
- 开工同步：确认项目、远端、分支和本地工作，安全获取更新后重新读取最新交接资料，再给出接手摘要。脏工作区、分叉和冲突先保留并报告，不覆盖、强推或自动改写历史。
- 收工同步：审查本次范围和验证结果，更新进展及确有变化的相关文档，将相关代码和文档一同提交、推送，并核对目标远端分支的实际提交。报告验证情况、下一步和仍只在本机的内容。
- 真实密钥、环境文件、凭据和业务数据不提交；必要变量和环境准备方法写在不含秘密的示例文件及说明中。
- 架构和重要技术决定变化时及时维护对应文档。进展中的“已完成”“已验证”“尚未验证”和“计划”应明确区分。
- 新电脑优先复现 README 的环境步骤；聊天历史、已安装依赖和本机配置不作为跨电脑可用的前提。
